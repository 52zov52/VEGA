# Управление полигонами (критерий «Управление полигонами», 0–5)

## Добавление участков

- Рисование кликами по глобусу (режим «Нарисовать»): название участка,
  живая площадь, отмена последней точки, минимум 3 точки.
- `POST /api/polygons` валидирует GeoJSON: тип Polygon, замкнутое кольцо,
  конечные координаты в диапазоне, bbox ≤ 10°, площадь ≥ 0.1 га — иначе 400
  с понятной причиной (показывается в UI). Ответ содержит посчитанные
  `area_ha` и `center` — участок сразу летит на карту и доступен для анализа.

## Удаление и переименование

- `DELETE /api/polygons/{id}` (404 на чужом id), кнопка «Удалить» в списке.
- `PATCH /api/polygons/{id}` — переименование (1–80 символов), inline в UI
  по клику на название (Enter/Esc).
- Хранилище переживает рестарт API: память + `data/polygons.json`
  (переменная `POLYGONS_FILE`), контракт под PostGIS не меняется.

## Автопоиск контуров региона

- При смене региона фронт запрашивает `GET /api/regions/{id}/fields` —
  контуры подхватываются автоматически, камера летит к региону.
- Слой Overpass/OSM (`pipelines/geodata/fields.py`): запрос `farmland`
  вокруг центра региона (`around`, радиус `OVERPASS_RADIUS_M`),
  парсинг узловой геометрии (`out geom`) в настоящие полигоны с центром
  и площадью; зеркала через запятую в `OVERPASS_API_URL` пробуются по порядку.
- Раньше ветка Overpass возвращала **пустые геометрии без центров** (поля были
  невидимы) и запрашивала весь bbox региона (таймауты) — исправлено.
- Без сети/при ошибке — честный fallback на demo-сетку; источник виден в UI
  бейджем «◉ OSM-контуры» / «◇ демо-сетка».
