# Автоматический сбор и подготовка данных (критерий, 0–5)

Анализ запускается одним кликом — датасет руками грузить не нужно:
`POST /api/analyze` сам тянет спутник и погоду, чистит, восстанавливает
и отдаёт ряд + ответ. Ниже — как устроена устойчивость.

## Источники (все — без ручной загрузки)

| Слой | 1-й источник | 2-й источник | Последний рубеж |
|---|---|---|---|
| Спутник | **Sentinel Hub Statistical API** (CDSE, нужен OAuth-клиент) | Sentinel-2 generic / Landsat / MODIS | parquet-кэш → demo-генератор |
| Погода | Open-Meteo: **ERA5-архив для прошлого**, прогноз для свежих дат | **NASA POWER** (проверен живьём, без ключей) | satellite-only режим |
| Контуры | Overpass/OSM вокруг центра региона | — | demo-сетка |

Ключевой фикс: раньше погода запрашивалась всегда через forecast-URL,
у которого **нет истории** — для окон 2023 года погода молча отсутствовала
(satellite-only). Теперь прошлое идёт в ERA5-архив, а если и он недоступен —
в NASA POWER (T2M/PRECTOTCORR/RH2M/радиация/влажность почвы). Проверено живым
запросом: окно 2023-05-01..10 → `nasa-power`, 10 строк, все колонки.

## Подготовка ряда (`preprocessing/clean.py` + engine)

- Нормализация дат/имён, облачность → пропуск (строка сохраняется — важно
  для разметки), медианная агрегация по полигону и дате, флаг `is_gap`.
- Слияние погоды по датам с приоритетом спутниковых колонок.
- Пропуски закрывает ансамбль (или линейный fallback) — метод виден в ответе.

## Частичная недоступность — контракт

- Каждый `fetch_*` либо возвращает данные, либо бросает внутрь цепочки;
  наружу — никогда 500: всегда частичный результат + `warnings` с причиной.
- Ответ `/api/analyze` содержит `sources` (что реально сработало) и новый
  блок `stats`: точек, закрытых пропусков, период. UI показывает панель
  «Конвейер данных» с этапами и источником каждого.

## Проверки

- `tests/test_providers.py` (6 тестов): выбор archive/forecast + кастомный URL,
  парсинг POWER (−999 → пропуск), цепочка fallback'ов вплоть до
  satellite-only, тотальный отказ спутника → demo, парсинг SH-ответа,
  наличие stats в ответе.
- Всего: тесты зелёные.

## Sentinel Hub: подключение (опционально, живой спутник)

1. SH Dashboard (`shapps.dataspace.copernicus.eu`) → User settings → OAuth clients →
   создать клиент → забрать `client_id` + `client_secret`.
2. В `.env`: `SENTINEL_SH_CLIENT_ID=...`, `SENTINEL_SH_CLIENT_SECRET=...`.
3. Проба: `py scripts/sentinel_probe.py` — должен вернуть ~20 точек NDVI за июнь.
4. Перезапустить API. В анализе источник станет `sentinel-2-sh`, геометрия
   полигона подтягивается автоматически (свои участки и контуры региона).
   Без кредов всё работает как раньше (demo), лимиты квоты не тратятся.

Статус: проверено живьём 06.09 — `sentinel_probe.py` вернул настоящий ряд
Sentinel-2 L2A за июнь 2023 (Ростов): NDVI 0.41–0.45, облачная неделя
пропущена, quality = доля валидных пикселей. Нюансы API, выясненные боем:
разрешение задаётся через `width/height` (resx игнорируется), в evalscript
обязателен выход `dataMask`, среднее за облачную неделю приходит строкой
`"NaN"` — такие слоты отбрасываются.
