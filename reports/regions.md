# Адаптивность под регионы (критерий, 0–5)

Привязки «Ростов или ничего» больше нет — ни на бэке, ни на фронте.

## Любой регион, а не 3 preset'а

- `POST /api/regions {name, center: [lat, lon]}` — новая территория в любой
  точке планеты (валидация: имя 1–80, центр в диапазоне). ID вида `custom-xxxxxx`.
- `DELETE /api/regions/{id}` — удаление своих (встроенные защищены, чужой id → 404).
- Персистентность `data/regions.json` (`REGIONS_FILE`), поиск включает кастомные.
- Оба пути контуров работают от центра, поэтому новый регион сразу полноценный:
  Overpass ищет farmland вокруг центра, иначе — demo-сетка вокруг него же.

## Координаты больше не захардкожены

- Было: погода и анализ всегда для точки 47.2/39.7 (Ростов) — для Краснодара
  и Воронежа подтягивались чужие метеоданные. Стало: фронт передаёт центр
  **конкретного поля** (анализ, сравнение, повтор), бэк — в погоду и SH-запрос.
- Центр региона для перелёта камеры — из ответа API (включая кастомные);
  локальный `REGION_COORDS` остался лишь запасным.

## Проверки

- `tests/test_api.py`: CRUD кастомных регионов, 400 на мусор, запрет удаления
  встроенных, контуры рядом с центром (Δ < 1°), 404 после удаления;
  координаты из запроса реально доходят до провайдера погоды.
- Руками: Ставрополье (45.3, 41.9) → 5 контуров вокруг центра, поиск находит.
- Всего: тесты зелёные, `tsc` чистый.

## Честные ограничения

- Demo-генератор фенологии настроен на юг РФ — для далёких широт fallback-ряды
  менее реалистичны (реальные источники — Overpass/SH/POWER — широтно-независимы).
- Сезонное окно анализа по умолчанию (май–сентябрь) задаёт фронт; для южного
  полушария его стоит поменять в запросе.

## Выбор без ввода + живой поиск (дополнение)

- В списке — 27 агрорегионов РФ с реальными центрами: выбрал и всё само
  (контуры, перелёт, анализ). Ничего вводить не нужно.
- Поиск умеет находить **любой регион мира**: живой Nominatim (OSM-геокодер,
  русские названия, троттлинг 1 запр/с + кэш, timeout 10с, при отказе —
  только локальный список). Выбор 🌍-кандидата автоматически регистрирует
  его как регион — дальше обычный конвейер.
- Ручной ввод lat/lon остался запасным путём.

## Скорость и стабильность контуров (дополнение)

- Было: запрос на весь bbox + relations (тяжёлые мультиполигоны — «криво»),
  каждый переход региона — до 30с ожидания, часто fallback в демо.
- Стало: только ways в радиусе центра, кольца >2000 точек и площади вне
  1–20000 га отбрасываются, **файловый кэш контуров на 7 дней**
  (`FIELDS_CACHE_TTL_SECONDS`) — повторный визит мгновенный, источник виден
  бейджем. Проверки: ways-only в запросе, попадание в кэш, отказ геокодера.
