# 🚀 Как развернуть VEGA на Render (пошагово на русском)

## ❓ Надо ли что-то вводить в переменные?

**Короткий ответ: почти ничего.** Всё нужное уже прописано в `render.yaml`.
Единственное, что Render спросит при установке, — два **необязательных** секрета
Sentinel Hub. Их можно оставить пустыми: API запустится в demo/fallback режиме
(погода — бесплатный Open-Meteo без ключа, спутник — синтетические данные).

| Переменная | Откуда берётся | Вводить вручную? |
|---|---|---|
| `APP_ENV=prod` | из `render.yaml` | нет |
| `WEATHER_API_URL` | из `render.yaml` | нет |
| `OVERPASS_API_URL` | из `render.yaml` | нет |
| `NEXT_PUBLIC_API_URL` | подставляется сам из адреса API | нет |
| `SENTINEL_SH_CLIENT_ID` | спросит Render при установке | **можно пусто** (тогда demo-режим) |
| `SENTINEL_SH_CLIENT_SECRET` | спросит Render при установке | **можно пусто** (тогда demo-режим) |

База Postgres и Redis **не нужны** — код их не использует
(полигоны хранятся в `./data/polygons.json`).

## 📦 Деплой (5 минут)

### Шаг 0. Удалите сломанный сервис
В прошлый раз сервис создался с окружением **Python 3.14** вместо Docker —
отсюда и ошибка сборки `scipy` (нет Fortran-компилятора `gfortran`).
Такой сервис не починить настройками, его надо удалить и создать заново
через Blueprint:

1. Откройте https://dashboard.render.com
2. Выберите упавший сервис → **Settings** → внизу **Delete Service**

### Шаг 1. Создание через Blueprint
1. Нажмите **New +** → **Blueprint**
2. Подключите репозиторий **52zov52/VEGA**, ветка `master`
3. Render прочитает `render.yaml` и покажет 2 сервиса:
   - `vega-api` — FastAPI (Docker, Python 3.11)
   - `vega-web` — Next.js фронтенд
4. В форме спросят `SENTINEL_SH_CLIENT_ID` / `SENTINEL_SH_CLIENT_SECRET` —
   оставьте пустыми (или вставьте свои ключи, если есть)
5. Нажмите **Apply**

### Шаг 2. Дождитесь сборки
- Сборка Docker-образа API занимает **10–20 минут** в первый раз
  (тянется большой `torch`, это нормально).
- Следить можно во вкладке **Logs** сервиса.
- Успех = статус **Live** + health-check `GET /api/health` отвечает `{"status":"ok"}`.

## 🌐 Адреса после деплоя

- **API:** `https://vega-api.onrender.com`
- **Документация (Swagger):** `https://vega-api.onrender.com/docs`
- **Фронтенд:** `https://vega-web.onrender.com`

Точные адреса покажет дашборд (суффикс может отличаться).

## ⚠️ Важно

1. **Free-план засыпает** после ~15 минут без запросов. Первый запрос
   после сна идёт 30–60 секунд (cold start) — это нормально.
2. **Секреты в `.env` засвечены.** `SENTINEL_SH_CLIENT_ID` и
   `SENTINEL_SH_CLIENT_SECRET` лежат в git-истории открытым текстом —
   перевыпустите их в личном кабинете Sentinel Hub и никому не показывайте.
   В `render.yaml` секреты НЕ захардкожены, они вводятся через дашборд.
3. **Фронтенд позже API.** `vega-web` при сборке забирает адрес API
   автоматически, но собирается независимо — если фронт упадёт,
   API всё равно будет работать.

## 🛠️ Если что-то пошло не так

1. Откройте **Logs** упавшего сервиса и смотрите хвост лога.
2. `Build failed` на `pip install` — проверьте, что сервис создан через
   **Blueprint** (окружение должно быть **Docker**, а не Python).
3. `Deploy failed` / health-check красный — смотрите логи запуска
   (runtime), обычно это опечатка в env-переменной.
4. Локальная проверка Docker-сборки:
   `docker build -f docker/api.Dockerfile -t vega-api .`
